## useFileProgress

Connects to `/api/nexa/progress/:fileId` via `EventSource` and streams real-time progress events.

```tsx
import { useFileProgress } from "@nexa-ed/react";

function UploadStatus({ fileId }: { fileId: string }) {
  const { progress, stage, message, isComplete, records, error } =
    useFileProgress(fileId);

  if (error) return <p>Error: {error}</p>;
  if (isComplete) return <p>Extracted {records.length} records</p>;

  return (
    <div>
      <p>{stage}: {message}</p>
      <progress value={progress} max={100} />
    </div>
  );
}
```

### Return value

| Field | Type | Description |
|-------|------|-------------|
| `progress` | `number` | 0–100 |
| `stage` | `string` | Current pipeline stage name |
| `message` | `string` | Human-readable status message |
| `isComplete` | `boolean` | `true` when extraction finished |
| `records` | `StudentRecord[]` | Extracted records (populated when complete) |
| `error` | `string \| null` | Error message if pipeline failed |

The hook automatically closes the `EventSource` connection when `isComplete` is `true` or the component unmounts.

## useNexaContext

Access the configured base path and other SDK context values:

```tsx
import { useNexaContext } from "@nexa-ed/react";

function MyComponent() {
  const { basePath } = useNexaContext();
  // basePath = "/api/nexa" (or whatever you set in NexaProvider)

  const res = await fetch(`${basePath}/rpc`);
}
```

This hook is used internally by all components — you rarely need it directly.

## OCR records hooks

All hooks below are exported from `@nexa-ed/react` and are `"use client"` — import them only in client components. They wire optimistic cache updates into the TanStack Query cache keyed by `getFileStudentRecords`.

<Callout type="info">
  The cache key is always built from `orpc.documents.getFileStudentRecords.queryOptions({ input: { fileId, page, limit, hasWarnings } }).queryKey`. Pass **identical values** to the hooks and to your `useQuery` call — they must target the same cache entry for optimistic updates to work.
</Callout>

### Optimistic update pattern

All mutating hooks follow the same three-step pattern internally:

1. **Cancel in-flight queries** for the affected cache key — prevents a stale refetch from overwriting the optimistic state.
2. **Patch the cache immediately** — the UI updates without waiting for the server.
3. **Roll back on error** — the previous data (saved in `onMutate`) is restored.

### `useColumnSort`

Client-side column sort state for `RecordDataGrid`. Cycles through `null → "asc" → "desc" → null` on each `toggleSort(col)` call. Numeric columns (where > 80% of values parse as numbers) use numeric comparison; all others use `localeCompare`. Null/empty values always sort last.

```ts
import { useColumnSort } from "@nexa-ed/react";

const { sortCol, sortDir, toggleSort, sortedRecords } = useColumnSort();
const displayed = sortedRecords(rawRecords); // sorted copy, original untouched

<RecordDataGrid
  records={displayed}
  sortCol={sortCol}
  sortDir={sortDir}
  onToggleSort={toggleSort}
/>
```

### `useUpdateRecordInList`

Optimistic mutation for updating a single record inside the paginated list cache. Rolls back on error.

```ts
import { useUpdateRecordInList } from "@nexa-ed/react";

const updateMutation = useUpdateRecordInList(fileId, page, limit, hasWarnings);
await updateMutation.mutateAsync({ recordId, recordData });
```

---

### `useAddRowsToList`

Optimistically appends new rows to the paginated cache, then creates them on the server. Returns a `handleAddRows` function rather than a raw `mutateAsync` — it accepts the **target page number** (not necessarily the current page) so rows land on the correct page in the cache.

```ts
import { useAddRowsToList } from "@nexa-ed/react";

const { handleAddRows, isPending, isError } = useAddRowsToList(fileId, page, limit, hasWarnings);
await handleAddRows(targetPageNumber, [{ name: "Alice", score: "92" }]);
```

---

### `useDeleteRecordFromList`

Optimistic delete from the paginated cache. Updates the `total` count in the pagination metadata immediately.

```ts
import { useDeleteRecordFromList } from "@nexa-ed/react";

const deleteMutation = useDeleteRecordFromList(fileId, page, limit, hasWarnings);
await deleteMutation.mutateAsync({ recordId });
```

### `useSerialRenumber`

Batch-renumbers a numeric column across all visible records on the current page. Optimistically patches the cache, sends server updates in chunks of 500, rolls back on error.

**Unusual signature:** requires an external `QueryClient` and `batchMutateAsync` so it can share the parent component's mutation instance rather than creating its own.

```ts
import { useSerialRenumber } from "@nexa-ed/react";
import { useBatchUpdateStudentRecords } from "@nexa-ed/react";
import { useQueryClient } from "@tanstack/react-query";

const queryClient = useQueryClient();
const batchMutation = useBatchUpdateStudentRecords();

const { handleRenumber } = useSerialRenumber(
  fileId,
  page,
  limit,
  hasWarnings,
  queryClient,
  batchMutation.mutateAsync
);

// Assigns "1", "2", "3"… to the "S/N" column in display order
await handleRenumber(records, "S/N", 1);
```

To continue a multi-page sequence, track `lastSerialNumber` from `onRenumberComplete` and pass `lastSerialNumber + 1` as `startFrom` on the next page.

### `useUpdatePageRecord`

## useUploadFile

Handles the full upload flow: get a presigned URL → PUT the file → submit for processing.

```tsx
import { useUploadFile } from "@nexa-ed/react";

function Uploader({ userId }: { userId: string }) {
  const { upload, isUploading, progress, fileId, error } =
    useUploadFile({ userId });

  return (
    <input
      type="file"
      accept=".pdf"
      onChange={(e) => {
        const file = e.target.files?.[0];
        if (file) upload(file);
      }}
    />
  );
}
```

### Return value

| Field | Type | Description |
|-------|------|-------------|
| `upload` | `(file: File) => Promise<string>` | Returns `fileId` on success |
| `isUploading` | `boolean` | `true` while upload + submit is in progress |
| `progress` | `number` | Upload byte progress 0–100 |
| `fileId` | `string \| null` | Set after successful submission |
| `error` | `string \| null` | Error message on failure |
